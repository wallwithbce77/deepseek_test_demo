## DF-002 EX009 的 item_count 字段语义存在歧义

- 现象：EX009 预期 `item_count=2`，模型返回 `item_count=100`。
- 复现：运行真实接口抽取测试，查看 EX009 的字段级评分。
- 定位：原始表格有 2 条明细，数量分别为 40 和 60。标注把
  `item_count` 定义为明细行数，模型将其理解为物料数量合计。
- 根因：字段名和抽取提示没有明确说明 `item_count` 的业务含义。
- 影响：单字段错误，字段准确率由 100% 降至 97.87%；当前仍高于
  85% 门禁，因此不会导致整体测试失败。
- 修复建议：
  1. 将提示中的字段说明改为“item_count：明细行数”；
  2. 或将字段重命名为 `line_item_count`；
  3. 增加 `total_quantity` 字段，明确区分明细行数和数量合计。
- 状态：待确认字段定义。


## DF-003 JSON 合规率判定过宽

- 类型：测试评估逻辑缺陷
- 涉及文件：`tests/test_extraction.py`
- 状态：代码已修改，待回归验证

### 问题

抽取提示要求原始回答仅包含一个 JSON 对象，但原实现先移除
Markdown 代码围栏，再将解析结果非 None 作为合规条件。

因此，带代码围栏的对象，以及数组、字符串、数字、布尔值等
非对象输出，也可能被计入 JSON 合规率。

### 修改

- 直接解析原始回答，不再提前移除代码围栏。
- 增加顶层类型检查，仅将解析结果为 dict 的回答计为合规。
- 保留原有统计公式和门禁阈值。

### 待验证场景

| 输出 | 预期结果 |
|---|---|
| 正常 JSON 对象 | 合规 |
| 带首尾空白的 JSON 对象 | 合规 |
| 带 Markdown 代码围栏的对象 | 不合规 |
| 数组、字符串、数字、布尔值、顶层 null | 不合规 |
| 语法错误的 JSON | 不合规 |

### 边界说明

本次只修正原始输出格式和顶层类型判断，不检查必需字段是否齐全，
也未增加 NaN、Infinity 等非标准数值的拒绝逻辑。

历史报告采用旧口径，不能直接与修改后的 JSON 合规率比较。
